## Оставшееся расхождение с документацией

`CreateOrderTest.testCreateOrderWithoutAuthorization`:

1. Получить актуальные ингредиенты через GET `/api/ingredients`.
2. Отправить POST `/api/orders` с валидными идентификаторами, без заголовка `Authorization`.
3. Проверить запрет создания заказа по формулировке на стр. 5 исходного PDF.

Ожидание теста: HTTP 401. Фактически: **HTTP 200**.
Тест сохранён падающим; нет `@Disabled`, повторных попыток или подмены ожидаемого статуса на 200.

В PDF есть неоднозначность: раздел POST `/api/orders` на стр. 1 не определяет отказ без токена,
а стр. 5 одновременно описывает требование авторизации и перенаправление в интерфейсе на `/login`.
HTTP 401 для POST выбран как предположение для защищённой операции; точный статус не указан в PDF.
Нужно уточнить у автора API, относится ли ограничение только к интерфейсу или также к API.
До уточнения тест сохраняет буквальное требование авторизации и не подгоняется под сервер.

Успешные статусы основных операций (200) и удаления пользователя (202) также не перечислены в PDF;
они явно приняты в тестах и подтверждены этим запуском. Для неверного хеша PDF задаёт только 500,
поэтому тело проверяется лишь на непустоту. Все эти ограничения отмечены в основном README.

## Очистка и отчёт

Все 15 созданных пользователей удалены: проверены HTTP 202 и `success: true` для каждого DELETE.
В отчёте есть 20 успешных шагов очистки; в пяти сценариях пользователь не создавался,
поэтому DELETE не требовался. `@AfterEach` выполняет очистку также после падения проверки.
Удаление заказов не реализовано, поскольку в документации такой операции нет.

Команда `mvn allure:report` завершилась успешно. Готовый [Allure HTML-отчёт](allure-report/index.html)
содержит все 20 результатов и шаги на русском, включая подготовку и очистку.
Проверены встроенные JSON-данные именно итогового HTML, а не только исходная папка результатов.
Поиск сгенерированных паролей и JWT в исходных и встроенных данных отчёта совпадений не нашёл.
Запросы и ответы с секретами целиком не прикладываются.

Визуальная проверка в браузере не выполнена: браузерный инструмент запретил протокол `file:`.
